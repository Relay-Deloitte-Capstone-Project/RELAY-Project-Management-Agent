## 1. WHAT THIS PIPELINE DOES

**Input:** A Jira ticket ID (e.g., `KAFKA-21002`)

**Output:** A plain-language summary of what code was changed for that ticket, generated by an LLM

**Data flow:**

```
Jira Ticket ID → Search GitHub commits (MCP) → Fetch code patches (REST API) → Build prompt → LLM summary
```

**Files produced in `corpus/`:**

| File | Purpose |
|------|---------|
| `github_commits_list.json` | Index of commits from MCP |
| `github_commit_detail.json` | Sample commit with patches (from REST) |
| `prompt_{TICKET}.txt` | The prompt sent to the LLM |
| `summary_{TICKET}.txt` | The LLM-generated summary + provider name |

---

## 2. ARCHITECTURE: MCP + REST HYBRID

We use **MCP for discovery** (listing/searching commits) and **direct GitHub REST API for content** (code patches/diffs).

| Layer | Tool | Role |
|-------|------|------|
| Discovery | `github-mcp-server` (stdio) | `list_commits`, `search_commits`, `list_pull_requests` |
| Content | Direct REST API | `GET /repos/{owner}/{repo}/commits/{sha}` → returns `files[].patch` |
| Generation | Groq → Gemini → Ollama | Fallback chain with hard timeouts |

**Why hybrid?** The official GitHub MCP server returns commit metadata but strips out the `patch` field (code diffs). We need actual `+`/`-` lines for meaningful LLM summaries.

## 6. KEY CODE PATTERNS

### 6.1 Finding Commits by Ticket ID

```python
import re


def find_commits_by_ticket(ticket_id: str, commits_data: list) -> list:
    pattern = re.compile(rf'\b{re.escape(ticket_id)}\b', re.IGNORECASE)
    matches = []
    for commit in commits_data:
        msg = commit.get("commit", {}).get("message", "")
        if pattern.search(msg):
            matches.append({
                "sha": commit["sha"],           # FULL 40-char SHA for REST API
                "sha_short": commit["sha"][:7],  # 7-char for display only
                "message": msg,
                "author": commit.get("commit", {}).get("author", {}).get("name", "unknown"),
                "date": commit.get("commit", {}).get("author", {}).get("date", ""),
            })
    return matches
```

> **Critical:** Always pass the **full 40-char SHA** to the GitHub REST API. Passing a 7-char short SHA causes `422 Unprocessable Entity`.

### 6.2 Fetching Code Patches (REST Fallback)

```python
import httpx

GITHUB_HEADERS = {
    "Accept": "application/vnd.github.v3+json",
    "Authorization": f"token {GITHUB_TOKEN}"
}


def get_commit_with_patches(sha: str) -> dict:
    url = f"https://api.github.com/repos/apache/kafka/commits/{sha}"
    resp = httpx.get(url, headers=GITHUB_HEADERS, timeout=15.0)
    resp.raise_for_status()
    return resp.json()
```

### 6.3 Prompt Construction

```python
def create_summary_prompt(ticket_id: str, commits: list, prs: list) -> str:
    commits_text = ""
    for c in commits:
        commits_text += f"\nCommit {c['sha_short']} by {c['author']} ({c['date'][:10]}):\n{c['message']}\n"
        if c.get("files_with_patches"):
            commits_text += "Changed files:\n"
            for f in c["files_with_patches"]:
                commits_text += f"  - {f['filename']}:\n{f['patch']}\n"

    return f"\nYou are a technical documentation assistant...\n\nCOMMITS:\n{commits_text}\n\nSUMMARY:"
```

### 6.4 LLM Fallback Chain

```python
import time


def generate_summary(prompt: str) -> dict:
    # Try 1: Groq (fastest, 20 req/sec)
    try:
        return {"summary": _call_groq(prompt), "provider": "groq"}
    except Exception as e:
        print(f"    ⚠️  Groq failed: {e}")

    # Try 2: Gemini (with retry)
    for attempt in range(2):
        try:
            if attempt > 0:
                time.sleep(3)
            return {"summary": _call_gemini(prompt), "provider": "gemini"}
        except Exception as e:
            print(f"    ⚠️  Gemini failed (attempt {attempt+1}): {e}")

    # Try 3: Ollama (local, no rate limits)
    try:
        return {"summary": _call_ollama(prompt), "provider": "ollama"}
    except Exception as e:
        print(f"    ⚠️  Ollama failed: {e}")

    return {"summary": "ERROR: All LLM providers failed.", "provider": "failed"}
```

### 6.5 Groq Call (Working Model)

```python
def _call_groq(prompt: str) -> str:
    url = "https://api.groq.com/openai/v1/chat/completions"
    headers = {
        "Authorization": f"Bearer {GROQ_API_KEY}",
        "Content-Type": "application/json"
    }
    payload = {
        "model": "llama-3.3-70b-versatile",  # llama3-8b-8192 is DECOMMISSIONED
        "messages": [{"role": "user", "content": prompt}],
        "temperature": 0.35,
        "max_tokens": 1024
    }
    resp = httpx.post(url, json=payload, headers=headers, timeout=15.0)
    resp.raise_for_status()
    return resp.json()["choices"][0]["message"]["content"]
```

### 6.6 Gemini Call (Google Cloud Key Format)

```python
def _call_gemini(prompt: str) -> str:
    # For AQ... keys: MUST use X-goog-api-key header, NOT ?key= query param
    url = (
        "https://generativelanguage.googleapis.com/v1beta/models/"
        "gemini-2.5-flash:generateContent"
    )
    headers = {
        "Content-Type": "application/json",
        "X-goog-api-key": GEMINI_API_KEY
    }
    payload = {
        "contents": [{"parts": [{"text": prompt}]}],
        "generationConfig": {"temperature": 0.35, "maxOutputTokens": 1024}
    }
    resp = httpx.post(url, json=payload, headers=headers, timeout=15.0)
    resp.raise_for_status()
    return resp.json()["candidates"][0]["content"]["parts"][0]["text"]
```

### 6.7 Ollama Call (Local Fallback)

```python
def _call_ollama(prompt: str) -> str:
    url = "http://localhost:11434/api/generate"
    payload = {
        "model": "llama3.1:8b",
        "prompt": prompt,
        "stream": False,
        "options": {"temperature": 0.35}
    }
    resp = httpx.post(url, json=payload, timeout=30.0)
    resp.raise_for_status()
    return resp.json()["response"]
```

> **Ollama setup (when needed):** `brew install ollama && ollama pull llama3.1:8b`

## 7. PROMPT TRUNCATION RULES

To stay within free-tier token limits, cap patches before building the prompt:

```python
MAX_FILES = 5      # Show top 5 changed files only
MAX_PATCH = 400    # 400 chars per patch

all_files = [...]  # from REST API
limited = all_files[:MAX_FILES]
files_with_patches = [
    {"filename": f["filename"], "patch": f["patch"][:MAX_PATCH] + "..."}
    for f in limited
]
if len(all_files) > MAX_FILES:
    files_with_patches.append({"filename": "... and N more files", "patch": "(truncated)"})
```

This keeps prompts under ~4,000 chars — well within all free-tier limits.
